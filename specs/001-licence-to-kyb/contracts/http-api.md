# Contract: HTTP API

- **Base path:** `/api`.
- **Format:** every body is JSON, except the file upload and the page images.
- **Authentication:** every endpoint except `POST /api/session`, `/healthz` and `/readyz` needs a valid session cookie. Without it, the response is `401` with `{ "code": "session_expired" }`.
  - Cookie: `HttpOnly`, `Secure`, `SameSite=Strict`, 8-hour expiry.
  - Every state-changing request must send the `X-CSRF-Token` header, matching the CSRF cookie. Otherwise the response is `403` with `{ "code": "forbidden" }`.
- **Error codes:** every error body has a `code` from the closed `ErrorCode` list in [data-model.md](../data-model.md#error-codes-api).
  - A request body that fails validation (a missing field, a value too long: business name over 200 characters, a reason or value over 500) is `422` with `{ "code": "invalid_request" }`. The details are not returned, because they can echo the submitted values.
- **Reasons:** reasons are machine-readable codes (`Reason.code` in [data-model.md](../data-model.md#reason-codes)). The UI maps each code to a string in `copy.ts`. Clients and tests use the codes, never the message text.
- **Contract source:** the OpenAPI schema generated by FastAPI. The frontend types in `frontend/src/api/generated.ts` are generated from it, and CI fails if the generated file is out of date.

## POST /api/session

Request: `{ "username": str, "password": str }`

| Status | Meaning |
|---|---|
| 200 | Session cookie set. Body: `{ "reviewer": str }` |
| 401 | `{ "code": "invalid_credentials" }` |
| 429 | `{ "code": "rate_limited" }`. Returned after more than 5 failed attempts in 1 minute for the account or the IP. Behind the frontend's nginx, the IP is the client's address (`X-Forwarded-For`), not the proxy's. |

## DELETE /api/session

Signs the reviewer out and clears the session and CSRF cookies. Like every state-changing request, it needs the session and the CSRF header.

| Status | Body |
|---|---|
| 204 | none |
| 401 | `{ "code": "session_expired" }` (no session, or it ended) |
| 403 | `{ "code": "forbidden" }` (no or wrong CSRF header) |

The session cookie is stateless: sign-out clears it in the browser, but a copy of the cookie stays valid until it expires.

## GET /healthz, GET /readyz

- `/healthz` returns `200` while the process runs.
- `/readyz` returns `200` only when the database and the checkpointer are reachable, and `503` otherwise.

## POST /api/runs

Request: `multipart/form-data` with these parts:
- `file` (PDF, JPG or PNG; at most 10 MB, 5 pages and 50 megapixels per page)
- `applicant_name` (str, 1 to 200 characters)

| Status | Body |
|---|---|
| 202 | `{ "run_id": uuid, "status": "processing" }`. Processing starts in the background. |
| 200 | `{ "run_id": uuid, "status": <current>, "duplicate": true }`. An identical file was uploaded before. |
| 422 | `{ "reason_code": "invalid_type" \| "too_large" \| "too_many_pages" \| "image_too_large" \| "unreadable_file", "run_id": uuid }`. Also recorded as a run with the route `reject`. |
| 422 | `{ "code": "invalid_request" }`: a part is missing or out of range (for example `applicant_name` longer than 200 characters). |

## GET /api/runs

Response: `{ "runs": [RunSummary] }`, newest first.

`RunSummary` contains `run_id`, `created_at`, `applicant_name`, `route`, `status`, `cost_usd` and `duration_ms`.

## GET /api/runs/{run_id}

Response `RunView`:

```json
{
  "run_id": "uuid",
  "applicant_name": "Fuller Services LLC",
  "created_at": "2026-11-22T08:00:00.000Z",
  "status": "received | processing | rejected | awaiting_review | awaiting_submit | done",
  "steps": [{ "name": "preprocess", "state": "done | running | pending | skipped", "duration_ms": 120 }],
  "route": "ready | needs_review | reject | null",
  "reasons": [{ "code": "near_expiry", "field": "expiry_date", "rule_id": "expiry", "detail": { "days": "10" } }],
  "form": { "version": 2, "fields": { "<form_field>": FormFieldView } },
  "form_approved": false,
  "required_documents": ["memorandum_of_association", "..."],
  "pages": 1
}
```

- `form` is `null` when processing stopped before a form existed; the reviewer can then retry or reject.
- `form_approved` is `true` only when an approval exists for the current form version. Submit needs it.
- `detail` holds the values a reason or rule result needs for its sentence (for example `days`). It never holds personal data.
- `required_documents` holds document codes; the UI maps each one to a name.

`FormFieldView`:

```json
{
  "value": "2026-12-25",
  "state": "passed | flagged | approved | corrected | overridden | needs_examination",
  "status": "present | not_present | unclear (what the licence shows for this field)",
  "origin": "read | entered_by_reviewer",
  "evidence_quote": "Expiry Date 25/12/2026",
  "evidence_box": { "page": 1, "x": 0.62, "y": 0.11, "w": 0.2, "h": 0.03 },
  "confidence": { "score": 0.81, "threshold": 0.9, "signals": { "agreement": 0, "grounding": 0.97 } },
  "rule_results": [{ "rule_id": "expiry", "severity": "warn", "outcome": "passed | failed | could_not_run | not_applicable", "reason_code": "near_expiry", "overridable": false, "detail": { "days": "10" } }],
  "model_rationale": "string or null (the resolver's explanation: model output)",
  "proposal_accepted": "bool or null (whether the resolver's proposal replaced the value)"
}
```

`404` with `{ "code": "not_found" }` if the run does not exist.

## GET /api/runs/{run_id}/pages/{n}

Response: `image/png`. `404` with `{ "code": "not_found" }` if the run or the page does not exist.

## POST /api/runs/{run_id}/review

Request:

```json
{
  "form_version": 2,
  "decisions": [
    { "decision_id": "uuid", "field": "expiry_date", "action": "approve" },
    { "decision_id": "uuid", "field": "licence_number", "action": "correct", "value": "1234567", "reason": "QR code shows this number" },
    { "decision_id": "uuid", "rule_id": "registry", "action": "override", "reason": "Registry service down; licence checked by phone" }
  ],
  "approve_form": false,
  "reject_case": false,
  "reject_reason": null,
  "action_id": "uuid"
}
```

- **Idempotency:**
  - The client generates a `decision_id` for each field decision, and one `action_id` for the request's form-level action (`approve_form` or `reject_case`).
  - An ID that was already applied is ignored, and creates no second audit event.
  - A new action, such as a second reject after a reopen, carries a new ID, so it is always recorded.
- **Partial review:** each call resumes the paused run, applies the decisions, and pauses it again. The run leaves review only when `approve_form` or `reject_case` is set.
- **When it applies:** runs in `awaiting_review` or `awaiting_submit`. A `ready` run is approved with `approve_form` and no decisions.
- **Flagged field:** a form field with state `flagged` or `needs_examination`. `approve_form` needs a decision on every flagged field (`undecided_fields`).
- **Blocking checks:** an `approve` or `correct` decision is refused with `blocking_rule_failed` when a rule with severity `block` fails on that field after the re-check. For example, an approved expired date or a corrected number in the wrong format.

| Status | Meaning |
|---|---|
| 200 | Updated `RunView`. The form version increases whenever the form's content changes: any value, or any field state. |
| 409 | `{ "code": "blocking_rule_failed" \| "not_overridable" \| "undecided_fields" \| "stale_version" \| "reason_required" \| "no_form", "field": str \| null, "rule_id": str \| null }`. `no_form`: processing stopped before a form existed; only `reject_case` is allowed. |

## POST /api/runs/{run_id}/reopen

Request: `{ "action_id": uuid, "reason": str (1 to 500) }`. This applies only to runs with status `rejected`.

| Status | Body |
|---|---|
| 200 | Updated `RunView`, with status `awaiting_review` |
| 409 | `{ "code": "not_rejected" }` |

## POST /api/runs/{run_id}/submit

Request: `{ "action_id": uuid, "form_version": int }`

| Status | Body |
|---|---|
| 200 | `{ "submission_id": uuid, "verified": bool }`. A repeated call with the same `action_id`, or for the same approved `form_version`, returns the same `submission_id`. |
| 409 | `{ "code": "not_approved" \| "stale_version" \| "not_awaiting_submit" \| "no_form" }` |

When `verified` is `false`, the run returns to `awaiting_review`, with reason code `verification_failed`. The verification failure raises the form version as a `system` change. The reviewer examines the form, approves the new version and submits it with a new `action_id`. This works even when no value changes. The run is `done` when its latest submission is verified.

## POST /api/runs/{run_id}/retry

Request: `{ "action_id": uuid }`. This applies only to runs in `awaiting_review` with reason code `processing_failed` or `budget_exhausted`. It sends the run back to `processing` from its last completed step.

| Status | Body |
|---|---|
| 202 | `{ "run_id": uuid, "status": "processing" }` |
| 409 | `{ "code": "not_retryable" }` |

As an alternative to a retry, the reviewer can enter values by hand: a `correct` decision on a `not_present` field records the value with origin `entered_by_reviewer`.

## GET /api/runs/{run_id}/trace

Response: `{ "spans": [SpanView] }`. Each `SpanView` contains `span_id`, `parent_id`, `kind`, `name`, `latency_ms`, `input_tokens`, `output_tokens`, `cache_read_tokens`, `cost_usd`, `model` and `summary`. Personal data is masked.

## GET /api/metrics/summary

Response for the current day (UTC). Counted over runs created today that finished processing:

| Field | Meaning |
|---|---|
| `runs` | how many runs |
| `refusal_rate` | share of runs with at least one model call the model refused |
| `fallback_rate` | share of runs with reason code `fallback_model` |
| `review_rate` | share of runs routed `needs_review` |
| `cost_usd` | the sum of the cost of today's model-call spans |
| `budget_tokens_remaining` | the daily token budget minus the tokens used today |

Example:

```json
{ "runs": 42, "refusal_rate": 0.0, "fallback_rate": 0.02, "review_rate": 0.31, "cost_usd": 6.10, "budget_tokens_remaining": 1250000 }
```
